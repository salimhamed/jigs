# A hub is every factory's only way to hear from providers

Status: accepted

A factory hears from its providers three ways today: webhooks to its own public
URL ([0003](./0003-webhook-ingress-resource-scoped-tokens.md)), a Slack socket,
and a poll that is the floor under both
([0011](./0011-event-triggers.md)). Each factory also holds its own provider
identity ([0009](./0009-factory-identity-per-provider.md)). Three needs do not
fit that shape: a GitHub App has exactly one webhook URL for every repository it
is installed on; a Linear agent's mentions arrive only on its OAuth app's
webhook and need a reply within 10 seconds; and installing a Linear app in
another workspace needs a browser callback and refresh tokens that outlive a
restart. So jigs gains a **hub**: a separate service that receives every
provider event, holds every app's credentials, and serves the factories of one
or more **Organizations**. Once it ships it replaces 0009, the ingress of
0003 and the poll and delivery kinds of 0011, and the installation token that
[0012](./0012-agents-act-as-the-factory-app.md) gives agents comes from the hub.

- **The hub is the only event path, and every factory needs one.** Ingress,
  the poll, Slack Socket Mode and their settings are removed, for all four
  providers (GitHub, Linear, Slack and PagerDuty) in the first release. A factory
  long-polls its hub; for each provider event it runs today's routing (hook
  tokens to a wake, or the trigger engine's push), then confirms its cursor.
  A wake still carries nothing and the run re-reads its provider, so a
  repeated event is harmless and an occurrence is still started at most once.
- **The hub keeps each factory's provider events** in order, for a
  configurable retention (about 7 days by default). A factory whose cursor
  is older than the retention is told, logs it loudly, and wakes every waiting run once.
  Occurrences older than the retention are lost. Nothing recovers an event a
  provider failed to send, now that no poll catches it, until such losses are
  seen.
- **Apps belong to an Organization**, several per provider, each assigned to
  chosen factories. A provider event goes only to the factories assigned to the
  app it came through, and a factory gets tokens only for its assigned apps.
  The Organization is read from the event (installation, Linear organization,
  Slack app), never from a hub-wide default.
- **The hub holds every credential, encrypted with a key from its
  environment, and issues short-lived tokens.** Factory
  identity modes are removed: a factory's `.env` holds its hub token and its
  model keys, nothing else. Apps are created by hand on each provider and
  installed through the provider's own OAuth or install flow, with the callback
  on the hub. Linear connects every workspace, the operator's own included,
  through consent as the app.
- **A Linear mention or assignment starts a run through an event-trigger
  source**, and reaches every assigned factory. The hub posts the first
  reply itself to meet the 10-second rule. Two factories that both take a
  mention both start runs; avoiding that is the factory author's job, through
  one Linear app per purpose or trigger filters. Progress in Linear's agent
  panel, replies and its stop button are a conversation
  ([0016](./0016-linear-agent-conversations.md)).
- **The protocol is factory-initiated only.** One ordered message list per
  factory with cursor confirmation, typed message kinds (`event` first), long
  polling, and token requests over plain HTTPS. The factory sends its jigs
  version for display; nothing compares it, and the hub and its factories run
  the same release.
- **The hub ships from this repository** as `@jigs-ai/hub` on npm, versioned
  with `@jigs-ai/jigs`, beside a private protocol package bundled into jigs. It
  is one Node process and its own Postgres database, configured entirely by
  environment, and it migrates its schema on start. Logins use GitHub through
  Better Auth, with admin and member roles and invite links; the first admin is
  named by email in the environment.

## Consequences

- As built, three details differ from the decision above. A PagerDuty app
  is not installed through an OAuth flow: the hub holds a Scoped OAuth app's
  client credentials with its account's subdomain and region, and mints a
  token that acts as the app for every factory request. Each Slack app keeps,
  on the hub, the bot scopes its installs ask for: jigs's list plus any an
  admin adds. And
  `HUB_PUBLIC_URL` must be a bare origin, because every webhook, callback and
  setup URL the hub shows is built from it.

- Decided 2026-10-05, and built before the hub's first deploy: a factory may
  be assigned several installations per provider, including several apps in
  one workspace, and names the one it means on every call. Nothing picks "the
  only one", and nothing is inferred from a git remote. An admin names each
  installation on the hub (the installation name), unique in the
  Organization. A PagerDuty app's `from` email lives on its installation,
  checked against the account's users when saved. `slackBotScopes` gains
  `reactions:write` and `files:write`, the hub refuses a Slack scope list that
  drops any of them, and a factory no longer lists its own Slack scopes.
  As built: every token request names its installation, and the hub answers
  404 for a name that is not an installation of an app assigned to the
  factory. Each provider event carries its installation's name, resolved when
  the factory reads it, so naming an installation later labels its undelivered
  events; it is `null` while unnamed, and the factory ignores such events. A
  binding names its GitHub installation, and the factory configuration lost its
  `pagerduty` and `slack` sections.

- Decided 2026-10-06: a `prompted` agent session event, a reply or a stop,
  goes to the factory like any provider event. The factory injects it into a
  live turn and wakes the session hook; the hub posts nothing for it, and only
  the `created` event gets the hub's first reply. See
  [0016](./0016-linear-agent-conversations.md).
- A solo operator runs a hub too, on the same machine behind a tunnel such as
  Tailscale Funnel. The factory itself never needs a public URL.
- A hub that is down stops every run from progressing, though nothing is lost
  within the retention. The poll's "always eventually correct" is traded for a
  single path.
- A hosted hub serving many companies with official apps is the same code with
  more than one Organization. Billing, rate limits between Organizations and the
  rest of running it for others wait until then.
- Run dashboards stay in each factory. The hub is Organization management and
  integrations only.
- Rejected: the hub beside the poll (two paths to keep and explain); a factory
  copy of each app's key (every member holds keys that act in every
  installation, and other workspaces' Linear installs still need a callback);
  the hub claiming a mention for one factory (a protocol request for what
  configuration already solves); version checks or compatibility shims between
  hub and factory (the project has one user and upgrades both together); a
  second repository (a factory cannot run its end-to-end test without a hub, so
  the two change together).
